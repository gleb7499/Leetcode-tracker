# Техническое задание (личная рабочая версия)

## 1. Суть проекта

Leetcode Tracker — система для регулярной практики задач по алгоритмам с механикой интервального повторения.

Ключевая идея:

- пользователь добавляет задачи и решает их в удобном ритме;
- система оценивает качество запоминания по результатам повторов;
- задачи автоматически планируются на будущие даты;
- пользователь видит динамику прогресса и предстоящую нагрузку.

Проект должен оставаться простым в использовании, но архитектурно готовым к росту.

## 2. Фиксированный технологический стек

Это единственный актуальный стек проекта:

- Frontend: React + Vite + TypeScript;
- Backend: Java + Spring (экосистема Spring);
- База данных: PostgreSQL.

Если в старых документах встречаются другие технологии, их следует считать устаревшими и не использовать как основу для новых решений.

## 3. Архитектурная модель

Проект развивается в сторону клиент-серверной архитектуры.

Основные части системы:

1. Web-клиент (Frontend)
   - интерфейс для задач, повторений, статистики и настроек;
   - основной пользовательский сценарий проходит через браузер.

2. API и бизнес-логика (Backend)
   - управление задачами, повторениями, статистикой и пользователями;
   - расчёт дат следующего повторения;
   - авторизация и контроль доступа.

3. Слой хранения данных (PostgreSQL)
   - централизованное хранение пользователей, задач, ревью и аналитики;
   - основа для синхронизации между устройствами.

4. Мобильный контур (перспектива)
   - Android-клиент как дополнительный канал доступа;
   - поддержка уведомлений о необходимости повторения.

## 4. Функциональные требования

### 4.1 Работа с задачами

- добавление задач вручную;
- поддержка ссылок на задачи (например, LeetCode);
- хранение заметок, сложности, тем и пользовательских меток;
- редактирование и удаление задач.

### 4.2 Сценарий повторения

- режим повторения одной задачи;
- режим последовательного повторения всех задач, назначенных на текущий день;
- фиксация результата попытки через статусы качества воспоминания.

### 4.3 Статусы после повторения

- Don’t Remember;
- Partially Remember;
- Remember Well.

От выбранного статуса зависит дата следующего показа задачи.

### 4.4 Статистика и прогресс

- количество повторений по дням;
- соотношение успешных и неуспешных повторов;
- динамика качества запоминания во времени;
- нагрузка на будущие дни;
- прогресс по темам, сложности и выбранным срезам.

### 4.5 Синхронизация

- данные должны быть едиными между клиентами;
- пользователь должен видеть актуальное состояние задач после входа в аккаунт на любом устройстве.

### 4.6 Уведомления

- напоминания о задачах, запланированных на сегодня;
- отдельный приоритет для Android-уведомлений;
- возможность расширения до web-уведомлений.

## 5. Нефункциональные требования

- предсказуемость и стабильность основной логики интервального повторения;
- производительность на типичных пользовательских объёмах;
- безопасная авторизация и защита пользовательских данных;
- готовность к развёртыванию в контейнерной среде;
- масштабируемость по мере роста числа пользователей и задач.

## 6. Модель данных (PostgreSQL, концептуально)

Минимальный набор сущностей:

- users: пользовательские аккаунты и атрибуты профиля;
- tasks: карточки задач и их метаданные;
- tags: нормализованные теги/темы;
- task_tags: связь задач и тегов;
- reviews: история повторений с результатами;
- schedules: актуальные даты следующих повторений;
- auth/session данные и служебные таблицы для авторизации;
- агрегаты/представления для статистики.

Конкретная схема может эволюционировать, но PostgreSQL остаётся обязательной БД.

## 7. Интервальное повторение

Система должна поддерживать:

- короткие интервалы при плохом воспоминании;
- увеличение интервалов при стабильном успешном воспоминании;
- пересчёт даты следующего повторения после каждого ревью;
- сохранение полной истории ревью для аналитики и восстановления контекста.

## 8. Экранная логика продукта

### Главный экран

- список задач на сегодня;
- быстрый вход в режим повторения;
- видимость текущей дневной нагрузки.

### Экран добавления задачи

- создание новой задачи и заполнение метаданных;
- возможность работы с задачами из внешних источников.

### Экран повторения

- отображение содержания задачи и контекста;
- выбор результата попытки;
- переход к следующей задаче без лишних шагов.

### Экран статистики

- динамика активности;
- качество повторений;
- распределение будущей нагрузки.

### Экран настроек

- персональные параметры повторения и уведомлений;
- базовые пользовательские настройки интерфейса.

## 9. Текущее состояние проекта

- frontend уже развивается как отдельное приложение на React + Vite + TypeScript;
- backend в Java + Spring и полноценная интеграция с PostgreSQL являются целевым направлением ближайших этапов;
- текущие локальные/временные решения допустимы как промежуточный этап, но не должны менять целевую архитектуру.

## 10. План развития

1. Стабилизация frontend-потока задач и повторений.
2. Реализация backend API на Java + Spring.
3. Подключение PostgreSQL и миграция данных на серверную модель хранения.
4. Полная авторизация и синхронизация данных между устройствами.
5. Расширенная аналитика и уведомления.
6. Развитие мобильного контура.
